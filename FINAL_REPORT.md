# Финальный отчёт — KAZAI

## Реализовано

- Полноценное локальное веб-приложение с Node.js REST API и SQLite.
- Каталог стартапов: поиск, географический фильтр, направление, сортировка, карточки и подробные страницы.
- События и подробная страница мероприятия; дата и статус рассчитываются динамически.
- Серверная форма предложения проекта, сохранение в БД и очередь модерации.
- Защищённый вход администратора, сессии, роли, модерация и CRUD проектов/событий; снятие с публикации мягкое.
- Миграция базы, seeded данные, ограничения частоты запросов, валидация, salted scrypt, подготовленные SQL запросы, защита от XSS при выводе, secure cookie в production и security headers.
- Адаптивный интерфейс RU/KZ/EN с Roboto и спокойной системой карточек/навигации. Samsung Innovation Campus использован как ориентир ясной и доступной типографики, фирменная графика и шрифт Samsung не копировались.
- README с локальным запуском, настройкой секретов, созданием администратора и API.

## Технологии и архитектура

Node.js 22.13+, `node:http`, встроенный `node:sqlite`, HTML, CSS и JavaScript без внешних npm-зависимостей. Схема: `migrations/001_initial.sql`, `migrations/002_startup_geography.sql`; сервер и API: `server.mjs`; публичный интерфейс: `index.html`, `startup.html`, `event.html`; панель управления: `admin.html`; данные: `data/catalog.json` и постоянная локальная `data/kazai.sqlite`.

## Ограничения и публикация

Каталог намеренно мал и требует ручного фактчекинга перед масштабированием. SQLite подходит для демонстрации и локального запуска, но для высокой параллельной нагрузки следует перейти на PostgreSQL. Встроенный сервер рассчитан на локальную демонстрацию; production нужен с TLS reverse proxy, надёжным `SESSION_SECRET`, мониторингом, резервными копиями и формальной политикой приватности. Время мероприятия взято из ТЗ как целые календарные дни, поскольку расписание организатора с точными часами не подтверждено.

GitHub URL: отсутствует. Локальные коммиты: не созданы. Внешняя публикация не выполнялась.
